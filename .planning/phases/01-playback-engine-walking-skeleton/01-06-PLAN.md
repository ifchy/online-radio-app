# Phase 1 Plan 06: Playback recovers on its own — fallback streams, reconnect at the live edge, bounded retries

## Phase Goal

ROADMAP Phase 1 Goal (verbatim): "A user on a physical Android phone can start a Bulgarian station and it keeps playing on its own through screen-off, background, calls, headphone changes, network switches and dead primary streams. The live edge, correct Cyrillic now-playing and media controls all work." (This line is not in user-story form; see 01-01-PLAN.md "Phase Goal".)

<objective>
Replace the thin handler logic with the explicit, pure `PlaybackStateMachine` (RESEARCH Pattern 2; ARCHITECTURE Patterns 3–5). It covers fallback rotation with a two-round dead-on-arrival rule, the connect timeout and stall watchdog, reconnect with backoff and jitter, network-change handling, and the `RetryBudget` presets (D-10). The handler becomes the command executor. It also emits `EngineDiagnostics` for the debug panel (D-07) and implements next/previous within the `PlayContext`.

Purpose: PLAY-07, PLAY-08, PLAY-10, the PLAY-11 live edge on reconnect, and the PLAY-01 rule that the FGS stays alive while reconnecting. This is the core value: "playback never stops on its own".
Output: the state machine, the reconnect policy and budget, the connectivity port, the handler refactor, diagnostics, skip, and fakeAsync tests.
</objective>
