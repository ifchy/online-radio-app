4. .github/workflows/release.yml. Triggers: push of tags matching v*, and workflow_dispatch. Permissions: contents: read. Follow RESEARCH 805-840, with these steps in order:
   1. "Require signing secrets": fail with a clear message if any of ANDROID_KEYSTORE_BASE64, ANDROID_KEYSTORE_PASSWORD, ANDROID_KEY_PASSWORD or ANDROID_KEY_ALIAS is empty, so CI never falls back to debug signing (PLAT-04).
   2. Decode the keystore into $RUNNER_TEMP/upload.jks and write android/key.properties with printf from env-mapped secrets. Never echo values and never use set -x.
   3. actions/setup-java@v6.0.1 (temurin 17) and the flutter-action as in ci.yml. flutter pub get.
   4. `flutter build appbundle --release --build-number=${{ github.run_number }}` and `flutter build apk --release --build-number=${{ github.run_number }}`, so both artifacts of one run share a versionCode.
   5. Run `keytool -printcert -jarfile` on both the APK and the AAB, and fail if either output contains CN=Android Debug.
   6. The same debug-station strings check on the APK.
   7. actions/upload-artifact@v7.0.1: name eradioto-${{ github.ref_name }}, both files, if-no-files-found error.
   8. A final step with `if: always()` that removes $RUNNER_TEMP/upload.jks and android/key.properties.

5. docs/RELEASE-SIGNING.md (D-14), a step-by-step owner guide based on RESEARCH 849-865:
   - Create the upload keystore on the Mac with JDK 17 keytool: keytool -genkeypair, -storetype PKCS12, RSA 2048, validity 10000, alias upload.
   - Back up the .jks and its passwords in a password manager or offline. Never keep them in the repo or a cloud-synced repo folder.
   - base64 the keystore to a .b64 file, set the four secrets with `gh secret set` (or GitHub Settings → Secrets and variables → Actions), then delete the .b64.
   - Optionally create a local android/key.properties for local release builds; it is gitignored.
   - Trigger a build: push a tag vX.Y.Z (tag pushes use the workflow file in the tagged commit, so this works before the PR merges), or use Actions → release → Run workflow once the workflow is on the default branch.
   - Download the artifact and run `adb install -r app-release.apk`. Uninstall a locally debug-signed build first to avoid a signature mismatch.
   - Verify the signer with keytool -printcert -jarfile.
   - Enable secret scanning and push protection.
   - Upload key vs app signing key: Play App Signing holds the app key, and a lost upload key can be reset in Play Console (Phase 4).
   - The guide contains no secret values.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub secrets → release job runner | The upload key and passwords exist only inside tag/dispatch runs |
| fork pull request → CI | Untrusted code runs in ci.yml, which must have no secret access |
| third-party GitHub Actions → build | Action code executes with the job's permissions |
| CI artifact → owner's phone | The signed APK is sideloaded |
