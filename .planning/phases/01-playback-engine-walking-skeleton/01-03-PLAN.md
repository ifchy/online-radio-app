# Phase 1 Plan 03: Stations behind .pls/.m3u playlists and extension-less HLS play, and app-owned traffic is HTTPS-only

## Phase Goal

ROADMAP Phase 1 Goal (verbatim): "A user on a physical Android phone can start a Bulgarian station and it keeps playing on its own through screen-off, background, calls, headphone changes, network switches and dead primary streams. The live edge, correct Cyrillic now-playing and media controls all work." (This line is not in user-story form; see 01-01-PLAN.md "Phase Goal".)

<objective>
Add the Dart `StreamResolver` that turns a catalogue `StationStream` (progressive | hls | pls | m3u | unknown) into an ordered list of directly playable `ResolvedStream`s, and wire it into the engine so playlist-wrapped and extension-less HLS stations play. Add the HTTPS-only `AppHttpClient` guard for app-owned traffic and the http/https-only `MediaHttpClient` used for media resolution.

Purpose: STRM-02, STRM-03 and the Dart half of STRM-04. Neither just_audio nor ExoPlayer parses `.pls`/`.m3u`, and `AudioSource.uri` picks HLS only by extension (RESEARCH Pattern 4; PITFALLS Pitfall 7).
Output: resolver, parsers, both HTTP clients, handler and bootstrap wiring, and MockClient-based tests.
</objective>

5. lib/features/playback/engine/resolver/stream_resolver.dart: `HttpStreamResolver implements StreamResolver`.
   - Constructor: `HttpStreamResolver(MediaHttpClient client, Clock clock, {Duration ttl = const Duration(hours: 1), Duration timeout = const Duration(seconds: 5), int maxBytes = 65536, int maxDepth = 3, int maxCandidates = 10, int maxRedirects = 5})`.
   - Follow RESEARCH Pattern 4 (405-418) and ARCHITECTURE Pattern 6 (319-342):
     - The catalogue kind wins: progressive → [progressive], hls → [hls], with no network.
     - For pls, m3u and unknown, send `http.Request('GET', url)` with followRedirects true and maxRedirects 5, under the timeout. Read the byte stream until maxBytes, then cancel the subscription.
     - An audio/* Content-Type (except the mpegurl and scpls types) → progressive on the original URL, returned immediately without reading the body.
     - Decode the body as UTF-8 with allowMalformed. If isHlsPlaylist → one hls candidate on the ORIGINAL URL, never a variant URL. Otherwise, if the body contains a `[playlist]` header (case-insensitive) → parsePls; otherwise parseM3u. The base is the final response URL when the response implements BaseResponseWithUrl, else the request URL.

     - Keep only http/https candidates, cap the list at maxCandidates, and throw empty when nothing is left.
     - A non-2xx status → httpStatus.
   - Cache: Map<Uri, (DateTime expiresAt, List<ResolvedStream>)> keyed by stream.url, using clock.now(). Also keep a Map<Uri, Future<List<ResolvedStream>>> of in-flight requests so concurrent callers share one request. invalidate() removes the cache entry.
   - Never probe an audio stream body from Dart: dart:io rejects "ICY 200 OK" (Pitfall 7).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| playlist server (internet) → HttpStreamResolver | Untrusted playlist bodies, headers and redirects |
| resolver output → ExoPlayer | Only vetted http(s) URLs may cross into the native player |
| app code → future app-owned endpoints | Catalogue and Radio Browser traffic must stay on TLS |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Denial of Service | HttpStreamResolver (oversized or endless body, slow server) | high | mitigate | 64 KB read cap with subscription cancel, 5 s timeout, never reading audio bodies (the audio/* short-circuit). Unit-tested with MockClient.streaming. |
| T-03-02 | Tampering / Elevation of Privilege | resolver output handed to ExoPlayer (file:, content:, javascript:, intent: entries) | high | mitigate | Scheme allow-list (http/https) on every candidate and at MediaHttpClient.send. Unit-tested for each scheme. |
| T-03-03 | Tampering (MITM downgrade) | AppHttpClient | high | mitigate | Rejects non-https URLs and does not follow redirects to non-https targets (manual redirect handling). Unit-tested. |
| T-03-04 | Denial of Service | redirect loops / deep nesting | medium | mitigate | maxRedirects 5, nesting depth ≤ 3, ≤ 10 candidates. Unit-tested. |
| T-03-05 | Information Disclosure | request headers | low | mitigate | Only the eRadioto User-Agent (name, version, repo URL) is sent, with no identifiers. The exact string is unit-tested. |
| T-03-06 | Spoofing (SSRF-like LAN probing) | playlist entries pointing at 127.0.0.1 or private ranges | low | accept | Phase 1 plays only the owner-verified curated stations (01-04), so no untrusted playlist reaches the resolver. Revisit in Phase 2, when Radio Browser URLs arrive: block loopback and private ranges there. |
</threat_model>
