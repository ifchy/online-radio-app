# Phase 1 Plan 01: Walking skeleton — tap БГ Радио, hear it with the screen off

## Phase Goal

ROADMAP Phase 1 Goal (verbatim): "A user on a physical Android phone can start a Bulgarian station and it keeps playing on its own through screen-off, background, calls, headphone changes, network switches and dead primary streams. The live edge, correct Cyrillic now-playing and media controls all work."

> MVP note: this Goal line is not in user-story form ("As a …, I want to …, so that …"). The planner does not invent a story. Run `/gsd mvp-phase 1` if you want the Goal rewritten as a user story; the plans do not change.

The walking skeleton this plan proves is recorded in `.planning/phases/01-playback-engine-walking-skeleton/SKELETON.md`.

<objective>
Turn the empty repo into a runnable `bg.izk.radio` ("eRadioto") Flutter app and prove the whole playback architecture end to end on one real station: the station list → `AudioEngine` → `RadioAudioHandler` (audio_service) → `JustAudioStreamPlayer` (ExoPlayer), with the media notification, lock screen and headset buttons, in a **release** build on the owner's phone. Then add the Bulgarian/English state labels, an accessible mini-player and the write-once first-launch date.

Purpose: this is the highest-risk slice of the project. If the plugin stack, FGS, cleartext config or INTERNET permission misbehave in a release build, we find out after one commit, before any resilience code is layered on top (tracer-first).

Output: the scaffolded app, the domain contracts (`Station`, `StationId`, `StreamKind`, `PlaybackStatus`, `MediaId`, `PlayContext`, `AudioEngine`), the engine seam (`StreamPlayer`, `AudioSessionPort`), the FGS mapping table, a one-station list with a mini-player, BG/EN ARB files, `SettingsRepository.ensureFirstLaunchAt`, and tests. Scope note: `files_modified` is long because this is the walking skeleton. About 12 of the paths are generated (l10n, freezed, riverpod) and about 6 are `flutter create` template files edited in place. The blocking tracer gate splits execution into two sessions.
</objective>

<assumption_delta_decision>
Signal: the assumption-delta probe fired (`pluralization`, term "fallback": "If the primary stream is dead, a fallback stream plays").
- **Primary noun:** `Station.streams[]`, the ordered list of `StationStream` (primary first, then fallbacks), per D-04.
- **Decision: promote.** `Station` has **no** singular stream-URL field. The engine always plays `station.streams[i]`. The index being played is engine state (`PlaybackStatus.streamIndex`), not a station field. The Phase 2 catalogue schema (CAT-02: "prioritised `streams[]`") uses the same shape, so nothing has to be migrated later.
- **Rationale:** a station with several official endpoints is the normal case (D-03/D-04). A singular `url` alongside `streams[]` would let later code bypass rotation (PLAY-08).
- **Invariant test (accepted):** `test/features/catalog/station_test.dart` rejects a `Station` with an empty `streams` list, and the tracer test checks that the loaded URL is `station.streams.first.url`. Plan 01-06 adds the rotation test: stream 1 plays when stream 0 fails.
</assumption_delta_decision>
