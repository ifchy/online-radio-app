# Phase 1 Plan 09: A dead primary stream falls over to its fallbacks, and next/previous step through the list

## Phase Goal

ROADMAP Phase 1 Goal (verbatim): "A user on a physical Android phone can start a Bulgarian station and it keeps playing on its own through screen-off, background, calls, headphone changes, network switches and dead primary streams. The live edge, correct Cyrillic now-playing and media controls all work." (This line is not in user-story form; see 01-01-PLAN.md "Phase Goal".)

<objective>
Replace the thin handler logic with the explicit, pure `PlaybackStateMachine` (RESEARCH Pattern 2; ARCHITECTURE Patterns 3 and 5). This plan covers fallback rotation with a two-round dead-on-arrival rule, the connect timeout, the PLAY-10 guards for the connecting phase, and next/previous within the `PlayContext`. The handler becomes the command executor and emits `EngineDiagnostics` for the debug panel (D-07). Plans 01-10 and 01-12 add the reconnect and connectivity rows to the same reducer, and 01-13 adds the focus rows.

Purpose: PLAY-08, the PLAY-10 and PLAY-11 rules while connecting, and car/headset next/previous (PLAY-03). This is the "dead primary streams" part of the core value.
Output: the state machine, the handler refactor, diagnostics, skip, and pure plus fakeAsync tests.
</objective>

    - UserPlay → Connecting(streamIndex 0, round 0). The command list starts with StopTransport, ClearNowPlaying and StartTimer(connect, 10 s), then Resolve. The handler publishes playing true/loading BEFORE the Resolve command runs.
    - Connecting + a failure in the current generation (resolve failure, player failure or connect-timer fire) → the next candidate of the same stream, then the next streams[] index, with a new generation for each load. After the last stream of round 0 comes round 1 from stream 0.     - A dead-primary-shaped station (stream 0 fails at once) → stream 1 is loaded in the same round, and Playing follows its ready snapshot.
    - A slow primary (no ready within 10 s under fakeAsync) → the connect timer fires → stream 1.
    - Connecting + ready&playing → Playing. The connect timer is cancelled and time-to-audio (clock delta since the UserPlay) is recorded in diagnostics.
    - Every event stamped with a stale generation (late failure, snapshot or resolve result) produces no transition and no command.
    - UserPause or UserStop while Connecting cancels the connect timer; a resolve result arriving afterwards is discarded and nothing loads (PLAY-10).
    - Paused, PlaybackError or Idle + UserPlay/UserResume → Connecting with a fresh load at the live edge (PLAY-11). No seek command exists.
    - Diagnostics: every event → state transition is appended to a ring buffer of 50 entries, newest last.

   - EngineState, immutable with copyWith: `PlaybackStatus status`, `Station? station`, `PlayContext context`, `int generation`, `int streamIndex`, `int candidateIndex`, `int round`, `List<ResolvedStream> candidates`, `bool everPlayed`, `int? lastWorkingStreamIndex`, `DateTime? connectStartedAt`.

   - EngineCommand, sealed: StopTransport, Resolve(stream), Load(resolved, generation), ReleaseFocus, StartTimer(kind, duration, generation), CancelTimer(kind), CancelAllTimers, InvalidateResolution(stream), ClearNowPlaying, RecordTimeToAudio(duration).
   - `enum TimerKind { connect }`; plans 01-10 and 01-12 add more kinds.
   - `class EngineTimings` with const defaults: connectTimeout 10 s and maxDeadOnArrivalRounds 2. These are Claude's-discretion values from RESEARCH 336-341, kept in one place so they can be tuned on a device.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-01 | Tampering (unwanted playback) | stale async results after a user pause or stop | medium | mitigate | A generation guard on every async event, the connect timer cancelled on pause and stop, and only UserPlay/UserResume may leave Paused, Idle or PlaybackError; unit-tested (PLAY-10). |
| T-09-02 | Denial of Service (battery and data) | endless rotation over dead streams | high | mitigate | At most 2 dead-on-arrival rounds, then PlaybackError(allStreamsFailed) with StopTransport, ReleaseFocus and CancelAllTimers, so the FGS drops; unit-tested. |
| T-09-03 | Information Disclosure (privacy) | diagnostics event log | low | mitigate | The 50-entry ring buffer lives in engine memory only; nothing here writes it to storage or the network (01-11 prohibition). |
| T-09-04 | Tampering | skip commands from other apps | low | accept | Skip only moves within the list the user started from and plays curated stations; any Bluetooth device can already send it. |
</threat_model>
